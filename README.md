# Mini NPU Simulator

## 프로젝트 개요

Python으로 구현한 Mini NPU 시뮬레이터입니다.

입력 패턴과 필터의 같은 위치 값을 곱하고(Multiply) 누적해서 더하는(Accumulate) **MAC(Multiply-Accumulate)** 연산을 직접 수행하여 패턴을 판정합니다.

## 실행 환경

- `python 3.13.15`  
- 외부 라이브러리(NumPy) 사용 없음
- Python 표준 라이브러리와 반복문만 사용

## 실행 방법
프로젝트 폴더에서 다음 명령어를 실행합니다.  
```sh
python3 main.py
```

실행 후 두 가지 모드 중 하나를 선택합니다.

```sh
=== Mini NPU Simulator ===

[모드 선택]
1. 사용자 입력 (3x3)
2. data.json 분석
선택:
```

### 1. 사용자 입력 모드

3×3 필터 A, 필터 B, 패턴을 각각 **한 줄씩 공백** 으로 구분하여 입력합니다.   
입력이 완료되면 다음 내용을 출력합니다.

- 필터 A MAC 점수
- 필터 B MAC 점수
- MAC 평균 연산 시간
- 판정 결과 `A`, `B` 또는 `판정 불가`
- 3×3 MAC 성능 분석

행 또는 열의 개수가 맞지 않거나 숫자로 변환할 수 없는 값을 입력하면, 안내 문구를 출력하고 처음부터 다시 입력받습니다.

### 2. data.json 분석 모드

`data.json`에서 다음 크기의 필터와 패턴을 읽어 분석합니다.  
- 5×5
- 13×13
- 25×25

각 패턴은 `size_{N}_{idx}` 형식의 키를 사용하며, 키에서 `N`을 추출하여 같은 크기의 필터와 비교합니다.

각 케이스마다 다음 내용을 출력합니다.

- Cross 점수
- X 점수
- 판정 결과 `Cross`, `X`, `UNDECIDED`
- expected 값
- `PASS` 또는 `FAIL`
- 실패한 경우 실패 사유

분석이 끝나면 3×3, 5×5, 13×13, 25×25 MAC 성능과 전체 테스트 결과를 출력합니다.

## 구현 요약

### 1. MAC 연산

입력 패턴과 필터의 같은 위치 값을 곱한 뒤 모두 더합니다.

```text
score = Σ pattern[row][col] × filter[row][col]
```

MAC 연산은 외부 벡터 연산 라이브러리를 사용하지 않고 이중 반복문으로 직접 구현합니다.

### 2. 라벨 정규화

프로그램 내부에서는 다음 두 개의 표준 라벨만 사용합니다.

- `Cross`
- `X`

입력 데이터는 다음과 같이 정규화합니다.

| 입력 | 표준 라벨 |
|---|---|
| `+` | `Cross` |
| `cross` | `Cross` |
| `x` | `X` |

필터 키와 `expected` 값을 모두 같은 표준 라벨로 변환한 뒤 판정 결과와 비교합니다.

### 3. 점수 비교

부동소수점 계산에서 발생할 수 있는 미세한 오차를 처리하기 위해 `epsilon` 기반 비교를 사용합니다.

```python
abs(score_a - score_b) < 1e-9
```

두 점수의 차이가 `1e-9`보다 작으면 동점으로 판단하여 `UNDECIDED`를 반환합니다.

### 4. 데이터 검증

`data.json` 분석 시 다음 항목을 검사합니다.

- `filters`, `patterns` 존재 여부
- 패턴 키의 `size_{N}_{idx}` 형식
- `input`, `expected` 존재 여부
- 패턴과 필터의 N×N 크기
- 각 원소가 유효한 숫자인지 여부
- 패턴 크기에 맞는 Cross/X 필터 존재 여부

오류가 있는 경우 전체 프로그램을 종료하지 않고 해당 케이스만 `FAIL` 처리합니다.

### 5. 성능 측정

MAC 함수 호출 구간만 `time.perf_counter()`로 측정합니다.  
각 크기에 대해 MAC 연산을 **10회 반복**하고 평균 시간을 ms 단위로 출력합니다.

출력 표에는 다음 항목이 포함됩니다.

```text
크기(N×N)    평균 시간(ms)    연산 횟수(N²)
```


## 결과 리포트

현재 `data.json`에는 총 6개의 패턴 테스트가 있으며 실행 결과는 **3 PASS / 3 FAIL**입니다.

| Case | Prediction | Expected | Result |
|---|---|---|---|
| `size_5_1` | `UNDECIDED` | `X` | FAIL |
| `size_5_2` | `Cross` | `Cross` | PASS |
| `size_13_1` | `X` | `X` | PASS |
| `size_13_2` | `UNDECIDED` | `Cross` | FAIL |
| `size_25_1` | `UNDECIDED` | `X` | FAIL |
| `size_25_2` | `Cross` | `Cross` | PASS |

1. `expected`의 `+`, `x`와 필터 키의 `cross`, `x`는 비교 전에 각각 `Cross`, `X`로 정규화합니다.
2. 따라서 서로 같은 의미의 라벨이 문자열 표현 차이 때문에 잘못 `FAIL` 처리되는 문제를 방지합니다.
3. `size_5_1`은 Cross 점수와 X 점수의 차이가 epsilon보다 작아 `UNDECIDED`로 판정됩니다.
4. `size_5_1`의 expected는 `X`이므로 최종 결과는 `FAIL`입니다.
5. `size_13_2`도 두 필터 점수가 동점이므로 `UNDECIDED`로 판정되고 expected `Cross`와 달라 `FAIL`입니다.
6. `size_25_1` 역시 두 점수가 동점이므로 `UNDECIDED`가 되어 expected `X`와 달라 `FAIL`입니다.
7. 이 실패들은 라벨 정규화 오류가 아니라 현재 데이터의 점수와 epsilon 기반 동점 정책에 따라 발생한 결과입니다.
8. 부동소수점 값은 계산 과정에서 매우 작은 표현 오차가 발생할 수 있으므로 단순한 `==` 비교 대신 허용오차를 사용합니다.
9. `abs(score_a - score_b) < 1e-9`인 경우 동점으로 처리하여 미세한 수치 오차가 임의의 승자를 만드는 것을 방지합니다.
10. JSON 스키마, 행렬 크기 또는 값이 잘못된 경우 MAC 연산 전에 검증하며 해당 케이스만 `FAIL` 처리합니다.
11. MAC 연산은 N×N 배열의 모든 위치를 한 번씩 방문하므로 한 번의 MAC에 필요한 연산 위치는 `N²`개입니다. 
12. 따라서 MAC 연산의 시간 복잡도는 **O(N²)** 입니다.
13. 크기가 3×3, 5×5, 13×13, 25×25로 증가하면 연산 위치는 각각 9, 25, 169, 625개로 증가합니다.
14. 성능 측정은 각 크기별로 10회 반복한 평균값을 사용하며 파일 읽기나 콘솔 입출력 시간은 측정 대상에서 제외합니다.
