# e1-3

Python으로 구현한 **Mini NPU 시뮬레이터**입니다.  
입력 패턴과 필터 사이의 **MAC(Multiply-Accumulate) 연산**을 직접 수행하고, 점수를 비교해 패턴을 판정합니다.

> 과제 요구사항에 따라 **Python 표준 라이브러리만 사용**하며, NumPy/pandas 등 외부 라이브러리는 사용하지 않습니다.

### 4.2 `data.json` 분석 모드

프로그램은 `main.py`와 같은 폴더에 있는 `data.json`을 읽습니다.

처리 순서는 다음과 같습니다.

1. `filters.size_5`, `filters.size_13`, `filters.size_25` 필터를 로드합니다.
2. 필터 라벨 `cross`, `x`를 각각 `Cross`, `X`로 정규화합니다.
3. `patterns`의 `size_{N}_{idx}` 키에서 `N`을 추출합니다.
4. 같은 크기의 필터를 선택합니다.
5. 패턴과 필터의 크기 및 데이터 형식을 검증합니다.
6. Cross/X 필터 각각에 대해 MAC 점수를 계산합니다.
7. epsilon 정책으로 최종 판정을 수행합니다.
8. `expected`와 비교해 `PASS` 또는 `FAIL`을 출력합니다.
9. 전체 테스트 결과를 요약합니다.

## 5. 구현 요약

### 5.1 MAC 연산

MAC은 **Multiply-Accumulate**의 약자로, 같은 위치에 있는 값끼리 곱한 뒤 결과를 모두 누적해서 더하는 연산입니다.

수식으로 표현하면 다음과 같습니다.

```text
score = Σ pattern[row][col] × filter[row][col]
```

프로그램에서는 외부 라이브러리를 사용하지 않고 이중 반복문으로 직접 구현합니다.

```python
def mac(pattern, filter_matrix):
    total = 0.0

    for row_index in range(len(pattern)):
        for col_index in range(len(pattern[row_index])):
            total += (
                pattern[row_index][col_index]
                * filter_matrix[row_index][col_index]
            )

    return total
```

`N×N` 데이터에서는 모든 원소를 한 번씩 확인하므로 MAC 한 번의 연산 횟수는 `N²`, 시간 복잡도는 **O(N²)** 입니다.

### 5.2 라벨 정규화

프로그램 내부에서는 두 개의 표준 라벨만 사용합니다.

- `Cross`
- `X`

JSON의 라벨은 다음과 같이 변환합니다.

| 원본 값 | 표준 라벨 |
|---|---|
| `+` | `Cross` |
| `cross` | `Cross` |
| `x` | `X` |

예를 들어 `+`, `cross`, `Cross`가 같은 의미임에도 문자열을 그대로 비교하면 서로 다른 값으로 판단될 수 있습니다.  
따라서 비교 전에 모두 표준 라벨로 변환합니다.

### 5.3 epsilon 기반 동점 처리

부동소수점은 일부 십진수를 이진수로 정확하게 표현할 수 없습니다.

예를 들어 계산 과정에서 다음과 같은 값이 나타날 수 있습니다.

```text
0.9000000000000000
0.8999999999999999
```

두 값의 차이가 매우 작으면 실제 의미상 같은 점수로 보는 것이 더 적절합니다.

따라서 다음 정책을 적용합니다.

```python
abs(score_a - score_b) < 1e-9
```

조건을 만족하면 결과를 `UNDECIDED`로 판정합니다.

### 5.4 스키마 및 크기 검증

다음 항목을 검사합니다.

- 패턴 키가 `size_{N}_{idx}` 형식인지 확인
- 패턴이 `N×N` 크기인지 확인
- 필터가 `N×N` 크기인지 확인
- 각 행의 열 개수가 동일한지 확인
- 모든 원소가 숫자인지 확인
- `input`, `expected` 필드가 존재하는지 확인
- 대응하는 크기의 필터가 존재하는지 확인

오류가 발생해도 전체 프로그램을 종료하지 않고 해당 케이스만 `FAIL` 처리하며 실패 원인을 저장합니다.

### 5.5 성능 측정

MAC 함수 호출 구간만 `time.perf_counter()`로 측정합니다.

각 크기에 대해 **10회 반복 실행한 평균 시간**을 ms 단위로 출력합니다.

파일 읽기, 사용자 입력, 콘솔 출력 시간은 성능 측정 구간에 포함하지 않습니다.

## 8. 성능 분석

프로그램은 `3×3`, `5×5`, `13×13`, `25×25` 크기에 대해 MAC 연산을 각각 10회 반복하고 평균 시간을 출력합니다.

```text
크기       평균 시간(ms)    연산 횟수
-------------------------------------
3×3        실행 환경별 값          9
5×5        실행 환경별 값         25
13×13      실행 환경별 값        169
25×25      실행 환경별 값        625
```

연산 횟수는 다음과 같습니다.

| 크기 | 연산 횟수 `N²` |
|---:|---:|
| `3×3` | 9 |
| `5×5` | 25 |
| `13×13` | 169 |
| `25×25` | 625 |

실제 측정 시간은 CPU 상태, 운영체제 스케줄링 등 실행 환경의 영향을 받기 때문에 고정된 값이 아닙니다.  
따라서 프로그램 실행 시 직접 측정한 값을 출력합니다.

## 9. 결과 리포트

1. `data.json`의 expected 라벨 `+`, `x`를 그대로 비교하지 않고 각각 `Cross`, `X`로 정규화했습니다.
2. 필터 키 `cross`, `x`도 동일한 표준 라벨로 변환해 라벨 표현 차이 때문에 발생할 수 있는 잘못된 `FAIL`을 방지했습니다.
3. `size_5_1`은 Cross 점수와 X 점수가 epsilon 범위 안에서 같으므로 `UNDECIDED`가 됩니다.
4. `size_5_1`의 expected 값은 `X`이므로 실제 판정과 달라 `FAIL`입니다.
5. `size_13_2`는 Cross 점수와 X 점수가 모두 `7.5`이므로 `UNDECIDED`가 됩니다.
6. `size_13_2`의 expected 값은 `Cross`이므로 실제 판정과 달라 `FAIL`입니다.
7. `size_25_1`도 Cross 점수와 X 점수가 모두 `4.9`이므로 `UNDECIDED`가 되며 expected `X`와 달라 `FAIL`입니다.
8. 이 세 실패는 프로그램이 비정상적으로 계산한 결과가 아니라 제공 데이터의 동점 점수와 명시된 epsilon 비교 정책에 따라 발생한 결과입니다.
9. epsilon 없이 실수 점수를 단순 비교하면 `0.9`와 `0.8999999999999999` 같은 미세한 표현 차이만으로 승자가 정해질 수 있습니다.
10. 따라서 `abs(score_a - score_b) < 1e-9`인 경우 동점 처리함으로써 부동소수점 오차로 인한 불안정한 판정을 방지했습니다.
11. JSON 스키마 또는 배열 크기가 잘못된 경우 계산 전에 검증하고 해당 케이스만 `FAIL` 처리해 전체 프로그램이 중단되지 않도록 했습니다.
12. MAC 한 번은 `N×N` 배열의 모든 위치를 한 번씩 확인하므로 연산 횟수는 `N²`입니다.
13. 따라서 MAC 연산의 시간 복잡도는 **O(N²)** 입니다.
14. 입력 크기가 `3 → 5 → 13 → 25`로 증가하면 연산 위치 수도 `9 → 25 → 169 → 625`로 증가합니다.
15. 각 크기에서 10회 반복 측정한 평균값을 사용해 단일 측정값보다 실행 시간의 변동을 줄였습니다.
16. 파일 읽기나 콘솔 출력 시간을 제외하고 MAC 함수 호출 구간만 측정해 데이터 크기에 따른 계산 비용을 비교했습니다.
17. 실패 원인을 데이터/스키마 문제, 프로그램 로직 문제, 부동소수점 비교 문제로 나누어 확인할 수 있도록 구현했습니다.

## 10. 과제 설명용 핵심 포인트

### MAC이란?

같은 위치의 두 숫자를 **곱하고(Multiply)** 그 결과를 계속 **누적해서 더하는(Accumulate)** 연산입니다.

### 왜 AI에서 중요한가?

이미지 필터나 신경망의 가중치 계산에서는 곱셈과 덧셈이 매우 많이 반복됩니다.  
따라서 MAC은 AI 연산의 기본 단위 중 하나입니다.

### 필터로 패턴을 어떻게 판정하는가?

입력 패턴과 Cross 필터, X 필터 각각의 MAC 점수를 계산합니다.  
점수가 더 큰 필터를 입력 패턴과 더 유사한 필터로 판단합니다.

### 왜 라벨 정규화가 필요한가?

`+`, `cross`, `Cross`처럼 표현이 달라도 같은 의미일 수 있기 때문입니다.  
프로그램 내부에서 `Cross`, `X`로 통일하면 문자열 표기 차이 때문에 발생하는 잘못된 비교를 방지할 수 있습니다.

### 왜 epsilon이 필요한가?

컴퓨터의 부동소수점 계산에서는 수학적으로 같은 값도 아주 작은 차이가 생길 수 있습니다.  
따라서 차이가 `1e-9`보다 작으면 같은 값으로 보고 `UNDECIDED` 처리합니다.

### 왜 시간 복잡도가 O(N²)인가?

`N×N` 배열에는 총 `N²`개의 원소가 있고, MAC 연산은 모든 위치를 한 번씩 방문하기 때문입니다.
